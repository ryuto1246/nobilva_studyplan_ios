## 2. 🟠 タイマーの記録の正しさ (まとめて作り直す価値あり)

- **[実機]** 実行中に「閉じる」を押すと、確認なしで計測が消える。再度開くと 25:00 に戻っている。サーバのセッションは開いたまま残る。ホームには「計測中」の表示も Live Activity もない (`TimerView.swift:35`、エンジンがシートの中にある)
- 一時停止中は「開始」ボタンしか出ず、押すたびに `sessions/start` が呼ばれて新しいセッションができる。一時停止したまま「完了」できない (`TimerView.swift:104-129`)
- 「完了」の送信に失敗すると再送する手段がなく、学習時間が失われる (`TimerView.swift:190-204`)
- ポモドーロで完了すると、今いるフェーズの経過時間しか記録されない。休憩中に完了すると、休憩時間が学習時間として記録される (`PomodoroEngine.swift:159-174`)
- 実行中もモード切替のセグメントが押せる。誤タップすると計測が 0 に戻る (`TimerView.swift:62`)
- アプリが終了されると状態がすべて消える (永続化なし)
- タイマーモードは 0 になっても止まらず、超過分も記録される (`PomodoroEngine.swift:107-118`)
- 「開始」を二度押しすると、セッションが 2 つ作られる
- 記録してもホーム・計画タブの完了状態が更新されない
- **[実機]** 初回が「作業 (0 回目)」と表示される (1 ずれている)
- 計測中に画面が自動ロックされる (`isIdleTimerDisabled` 未使用)
- 良かった点: バックグラウンドから戻った時の経過時間は正しい (壁時計ベース) **[実機]**

## 3. 🟠 認証・セッション

- 同時に複数の 401 が来ても refresh を 1 本にまとめていない。refresh token の再利用検知でログアウトされうる (`APIClient.swift:111-128`)
- サーバの `/session/refresh` が Supabase の 5xx やタイムアウトも 401 で返すため、障害時に全員ログアウトされる (server `session/refresh/route.ts:26-29`)。c424bb6 で塞いだ問題がサーバ経由で残っている
- 起動時に一時エラーが出るとログイン画面に落ち、自動で復帰しない (scenePhase の監視なし)
- 強制ログアウト時に、APNs の解除・未読ポーリング・ローカル通知が片付かない。recovery リンクで別アカウントに切り替わっても、DiskCache が残る
- APNs の DELETE がユーザーの全端末のトークンを消す (server `settings/apns/route.ts:42-52`)
- 「おかえりなさい ○○ さん」が前のアカウントの名前のまま残る (`RememberedIdentity.swift:31-37`)
- Keychain が `AfterFirstUnlock` で ThisDeviceOnly でない。書き込み失敗も無視している
- パスワード変更で、現在のパスワードも再認証も求めない
- アカウント削除がアプリ内で完結しない (App Store の要件。サーバに API はある)

## 4. 🟠 ログイン画面 (実機)

- **[実機]** 「Face ID でログイン」を押すと、システムのシートが出ずに即失敗し、「パスキーが未登録の可能性」が出る。失敗理由 (ネットワーク / 期限切れ / 400) に関係なく同じ文言 (`LoginView.swift:288-293`)
- **[実機]** 上記の案内が差し込まれると、フォーム全体が約 80pt 下にずれる。押そうとしたボタンが動く
- ID 欄で Return を押してもパスワード欄に進まない (`.submitLabel(.next)` / `onSubmit` なし)
- 入力欄のアイコンや余白をタップしてもフォーカスが入らない
- パスキーの AutoFill (`performAutoFillAssistedRequests`) を使っておらず、パスワードとの複合リクエストにもなっていない。ID 欄をタップしても QuickType にパスキー候補が出ない (iOS の標準的な体験と違う)
- 「Face ID」固定表記。Touch ID の端末では不正確
- **[実機]** 無効状態の「パスワードでログイン」は白地に薄いグレーで、ボタンだと分かりにくい
- 両方のボタンで `isSubmitting` を共有しているため、スピナーが 2 つ同時に出る
- Claim / Recovery / パスキー管理: Face ID シートを閉じただけでエラーが出る。Claim のエラー画面から抜けられない。サーバの英語メッセージ (`claim link expired` など) がそのまま出る

## 5. 🟠 チャット

- 末尾に改行があると、送信後に吹き出しが二重になる。改行だけでも送信できる (`.whitespaces` で trim しているため、`ChatRoomView.swift:120,202`)
- 送信に失敗すると、入力した文章が消える
- 開いたまま届いたメッセージが既読にならない。読んだ後もタブバッジが最大 30 秒残る。ログアウト後も未読ポーリングが続く
- **[実機]** 日付の区切りがなく、時刻 (HH:mm) だけが並ぶ。別の日のメッセージが「01:15 → 01:09 → 16:14」のように前後して見える
- 吹き出しを長押ししてもコピーできない。画像をタップしても拡大・保存・共有ができない。画像の送信中に何も表示されない
- 開いたときにアニメーションで下までスクロールする。過去ログを読んでいるとポーリングで最下部へ引き戻される
- **[実機]** 会話画面でもタブバーが表示されたまま。入力バーが浮いたタブバーの上に重なり窮屈 (iOS のメッセージ系アプリは会話中タブバーを隠すのが一般的)
- **[実機]** 一覧に最終メッセージの時刻が出ない。毎回ローディングから始まる (キャッシュなし)
- 新しい講師をタップしても、スレッドを作るだけでチャットは開かない
- 送信・添付ボタンに VoiceOver 用のラベルがない。タップ領域も 44pt 未満
- 15 秒ごとに全件を取り直している (ページングなし)

## 6. 🟠 ホーム (Web 版 `app/(student)/dashboard` との比較を含む)

- **[実機]** 期限の日付が「2026-10-0 / 9」のように数字の途中で折り返される。科目タグも「その / 他」と割れる。メタ情報の HStack が横幅不足に対応していない (`TodoRow.swift:92-121`)
- **[実機]** 時刻が「09:00:00」と秒まで出る。日付が「2026-10-09」と ISO 形式のまま。Web は時刻を出さず朝/昼/夜で分け、日付は「10月9日(金)」形式
- **[実機]** タスク行のタイトルをタップしても何も起きない。Web は行全体がタイマーへのリンク
- **[実機]** 文言がタメ口 (「期限切れのタスクが 4 件あるよ。」「1つずつ片付けよう」「決めよう」)。決めている「落ち着いた敬体」と合わない。Web は「今日も頑張りましょう」など敬体
- 情報構造: Web は期限切れと今日の未完了を 1 本にまとめ、先頭 1 件を「まずはこれをやろう」で大きく出す。完了済みは隠す。iOS はセクションが分かれ、完了済みも残り、何から手を付けるかが分かりにくい
- 今日が全部完了したら明日の予定 (読み取り専用) に切り替える Web の挙動がない。iOS では明日の行も完了操作やタイマー起動ができてしまう
- 面談カード: Web にある状態バッジ (リスケ提案中など)・カウントダウン・「会議に参加」ボタン・新日時の提案がない
- 期限切れの「N日前」表示がない (Web は赤字で出す)
- **[実機]** 過去の単発「使えない時間」(10/9 の模試) が出続ける (Web も同じ穴)。チームの予定の「除外中」が見た目で区別できない。全行に意味のない人型アイコンが付く
- **[実機]** スクロールすると内容がステータスバーの裏に潜り、時計と重なる (ナビゲーションバーを隠しているため、スクロールエッジの背景がない)
- **[実機]** 画面ごとに大見出しの有無が違う (ホームはなし、計画・チャット・履歴・設定はあり)
- 前日のキャッシュが「今日の計画」として出る (日付チェックなし)。トグルが失敗しても元に戻らない
- 挨拶の時間帯判定が端末のタイムゾーン依存 (`Calendar.current`)
- 読み込み中・エラー画面では pull-to-refresh ができない

## 9. 🟡 設定

- **[実機]** 「プロフィール」の中にポモドーロがあり、グルーピングが不自然。項目が 1 つだけのセクションが 4 つ続き、縦に長い
- **[実機]** 学習設定: セクション見出し「学年」と行ラベル「学年」が重複。保存ボタンがフォーム内のカードにある (iOS ではナビゲーションバー右上か自動保存が一般的)。120 分をステッパーで変えるのはタップ回数が多い
- 取得の失敗を `try?` で握りつぶしている。#6 と重なると、初期値のまま保存する事故が起きる
- GuideView の NavigationStack が二重。本文が現在の UI と合っていない (「その他 > 面談」など)
- ログイン直後に説明なしで通知許可ダイアログを出している

## 10. 🟡 文字サイズ・アクセシビリティ

- **[実機] 最大の文字サイズ (AX-XL) でホームが崩壊する。** 期限の日付が 1 文字ずつ縦に並び、科目が消え、1 行が画面の高さを超える。HStack を大きな文字サイズで縦に組み替えていない (`ViewThatFits` か `dynamicTypeSize.isAccessibilitySize` で切り替えるべき)
- 標準の文字サイズでも、期限の日付が折り返す (§6)
- 固定サイズのフォント (TimerRing / 挨拶 30〜44pt / ChatAvatar) は Dynamic Type に追従しない
- 完了トグル (約 22pt)、相談・再生ボタン (28pt)、目のアイコン (24pt)、チャットの送信 (30pt) は HIG の 44pt 未満
- 完了トグル・送信・添付・コピー・パスワード表示に `accessibilityLabel` がなく、VoiceOver が SF Symbol 名を読む
- チームの予定のトグルが `Toggle("")` で、何のスイッチか読み上げられない
- 完了時のハプティクスがない
- 文字の大きさの階層: 本文に対して、ホームの挨拶と「期限切れのタスクが〜」が大きすぎる (largeTitle 級が 3 段重なる)。タスク名に対してメタ情報 (科目・時刻・分) が細かく 3 種類並び、視線が散る
